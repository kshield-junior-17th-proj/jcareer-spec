# J-Career 합성 MLOps 흐름도 해설

이 도면은 `feature_snapshot` 배치 경로만 보여 줍니다. 실제 AWS 배포·실행 결과가 아니며,
Lambda에서 회원·기업 DB로 직접 연결하는 경로는 현재 Terraform에 없습니다.

1. 별도 합성 Lab의 회원·기업 자료를 읽습니다.
2. DB 옆 내보내기 도구가 기술·경력·직무와 두 가지 단어 겹침을 숫자 특징 5개로 바꿉니다.
3. 숫자 자료 CSV 1개와 검증용 JSON 2개를 실행별 S3 입력 경로에 둡니다.
4. 사람이 확인 문자열과 입력값을 넣어 Lambda를 한 번 시작합니다. 확인 문자열은 인증·승인 증명이 아니며, 예약 일정이나 공개 API는 없습니다.
5. Lambda는 필수 3개 파일이 모두 있는지 확인합니다. 파일 크기와 해시, 허용 항목도 검사한 뒤 도전자 모델을 학습합니다. 같은 실행 경로의 다른 객체까지 찾아 차단하지는 않습니다.
6. 결과 6파일은 S3 결과 경로에, 실행 상태는 DynamoDB에 기록합니다.
7. 상태는 사람 검토 대기에서 끝나며 운영 추천으로 자동 연결하지 않습니다.

환경·입력 검증이 실행 상태 최초 기록 전에 실패하면 DynamoDB의 `FAILED_SAFE`가 남지 않을 수
있습니다. `RUNNING` 기록 뒤 처리 오류는 가능한 경우 `FAILED_SAFE`로 바꾸고 예외를 다시
발생시킵니다. 실패 기록 자체가 실패할 가능성도 별도 운영 관찰이 필요합니다.

단어 겹침은 의미 이해가 아닙니다. 지원 단계 표식은 합격 가능성·지원자 품질·채용 성공을
나타내지 않습니다. 이 흐름에는 SageMaker, Bedrock 임베딩, EventBridge 일정, API Gateway,
자동 배포, 자동 모델 승격이 없습니다.
