현재 추천 기준과 후보 모델을 같은 조건에서 비교할 수 있도록 자료, 실행 코드, 결과와 상태 기록을 한 묶음으로 관리합니다. 서비스 반영 여부는 담당자가 따로 검토합니다.

01

비교 목적

기술 70%, 경력 20%, 직무 10%로 계산하는 현재 기준과 후보 모델을 나란히 비교하기 위한 구조입니다.

02

데이터 범위

검증용 합성 회원, 기업, 지원 데이터를 사용합니다. 원문은 모델에 넣기 전에 다섯 가지 비교 수치로 줄입니다.

03

결과 상태

학습 결과와 평가 기록을 저장한 뒤 “사람 검토 대기” 상태로 마칩니다. 자동 승격은 허용하지 않습니다.

04

검증 범위

학습 코드와 Terraform 계획, 단위시험을 제공합니다. AWS 배포와 이미지 등록, 실행 관찰은 별도 검증 단계입니다.

MLOps 기술 명세

실행 단계마다
검증 지점을 둡니다

학습 코드와 Terraform에 반영된 현재 기준입니다. 모델 품질과 공정성, 서비스 승격 여부는 별도 평가 절차에서 다룹니다.

구성요소

  • 자료 변환 도구: 합성 원문을 다섯 가지 비교 수치로 변환
  • 파일 보관함(S3): 입력 파일 3개와 결과 파일 6개를 실행별로 분리
  • 작업 실행기(Lambda): 파일을 검사하고 시험 학습을 한 번 돌림
  • 상태표(DynamoDB): 실행 중·성공·실패를 기록하고 같은 번호로 덮어쓰지 못하게 함
  • 이미지·권한·로그(ECR·IAM·CloudWatch Logs): 실행 코드 보관, 접근 제한, 기록 저장

실행 전 검증

  • 합성 데이터 표식과 담당자 확인값이 없으면 즉시 중단
  • 실행 번호에 위험한 문자가 없는지 확인
  • 파일 종류, 개수, 크기, 파일 지문(SHA-256)이 예상과 같은지 확인
  • 정상 종료 상태는 “학습 완료, 사람 검토 대기”로 기록
  • 실행 중 오류가 나면 가능한 범위에서 “안전 실패”로 기록

실행 방식

담당자가 확인값과 실행 정보를 입력해 Lambda 작업을 한 차례 실행합니다. 외부 공개 API와 자동 실행 일정은 두지 않았고, 확인값은 의도하지 않은 실행을 막는 잠금장치로 사용합니다.

  • 허용 작업(action): 후보 모델 학습 한 종류만 허용
  • 실행 번호(run_id): 정해진 안전 문자만 사용
  • 자료 형태(source_mode): 숫자 비교 파일로 고정
  • 자료 위치(source_prefix): 그 실행에 정해 둔 폴더만 허용

데이터 이동

  1. 합성 DB 원문은 비교 수치로 바꾸는 동안만 읽습니다.
  2. 학습 파일에는 가명 번호, 비교 수치 다섯 개와 지원 진행 단계를 나타내는 표식만 넣습니다.
  3. 입력 파일 3개를 실행 번호별 보관함에 둡니다.
  4. 담당자가 시작하면 파일 검사, 시험 학습, 결과 저장이 차례로 이어집니다.
  5. 결과 파일 6개와 마지막 상태를 남긴 뒤 멈춥니다.

보안·운영 통제

  • 기본 설정은 꺼짐(disabled)이며 계획 수는 0
  • 다음 단계로 갈 때마다 정확한 확인값을 요구
  • 파일 보관함의 공개 접근과 암호화하지 않은 통신을 차단
  • 실행 이미지는 내용 지문으로 고정하고 등록할 때 검사
  • 동시에 한 건만 실행하며 외부 공개 호출 주소는 두지 않음
  • 기본 보관 기간은 자료·로그 7일, 실행 이미지 최근 5개
  • 상태표에는 자동 삭제 기한(TTL)이 없고 인프라는 별도로 정리할 때까지 남음
  • DB 주소, 비밀번호, VPC 연결과 자동 일정은 현재 구성에 포함하지 않음

오류 처리

  • 파일이 빠지거나 바뀌면 학습하지 않고 중단
  • 같은 실행 번호를 다시 쓰면 기존 상태를 덮지 않고 거부
  • 허용하지 않은 입력 항목이 들어오면 검사 단계에서 거부
  • 파일이나 상태를 저장하지 못하면 성공으로 표시하지 않음
  • 사람 검토가 끝나지 않으면 추천 서비스와 연결하지 않음
  • 아주 이른 단계의 오류는 실패 상태 기록도 남기지 못할 수 있음
